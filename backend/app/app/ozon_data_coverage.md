# Ozon Data Coverage

Дата обновления: 2026-06-01.

Сервис: `Лето СМ Платформа`.

## Подключено в MVP

- Текущий кабинет Ozon: `Аллея мебели`.
- Целевой магазин для BI: `Лето стройматериалы`.
- Режим использования: `benchmark_account` - временная аналитика и калибровка расчетов до появления собственного кабинета Лето СМ.
- Seller API:
  - проверка ключей без раскрытия секрета;
  - дерево категорий `/v1/description-category/tree`;
  - список товаров продавца `/v3/product/list`;
  - заготовка для цен `/v5/product/info/prices`.
- Performance API:
  - получение OAuth-токена `/api/client/token` без возврата токена наружу.

## Следующий слой для BI

- При использовании кабинета `Аллея мебели` все данные заказов, рекламы, цен и остатков должны отображаться с источником `benchmark_account`, чтобы не смешивать их с будущей фактической аналитикой Лето СМ.
- Каталог, цены, остатки: Seller API.
- Карточки, SKU, offer_id, категории: Seller API.
- Заказы и продажи своих товаров: Seller API postings/analytics/report endpoints.
- Реклама, кампании, расходы, DRR: Performance API и отчеты.
- Начисления, комиссии, возвраты, удержания: финансовые отчеты кабинета Ozon и доступные Seller API reports.
- Конкуренты, рыночные цены, спрос, поисковые запросы: если API не отдает метрику, использовать выгрузки из кабинета Ozon/разделов аналитики с явной пометкой источника.
- Калькулятор расходов: использовать как контрольную сверку; Ozon описывает XLSX-калькулятор как предварительный инструмент, поэтому фактические расчеты должны сверяться с тарифами и начислениями.

## Что нельзя подменять оценкой без пометки

- Комиссии по конкретной категории.
- Логистика FBO/FBS/realFBS.
- Баллы продавца и влияние акций.
- Конкурентные продажи и заказы.
- Фактическая прибыль после возвратов, отмен, компенсаций и удержаний.
